# Требуемые доработки редактора писем

Статус: требования зафиксированы, реализация не начата  
Дата фиксации: 2026-07-11  
Контур: редактор содержания рассылки  
Ответственное направление: техническое

## 1. Причина изменений

При production-проверке письма была подтверждена следующая граница текущего поведения:

- URL, вставленный в тело как обычный текст, сохраняется в HTML как текстовый узел, например `<div>https://example.org/</div>`;
- почтовый клиент может самостоятельно сделать такой URL кликабельным;
- Письмолёт при этом не создаёт запись в `tracked_links` и не учитывает переход;
- существующий механизм отслеживания работает только для ссылок, которые реально представлены в HTML как `<a href="...">`.

Дополнительно в текущем редакторе:

- выбор цвета текста перегружен полной палитрой;
- создание ссылки выглядит нестандартно и неочевидно;
- вставка форматированного текста может переносить лишние inline-стили и служебные свойства из внешнего источника.

## 2. Цели

Упростить редактор для нетехнического пользователя и сделать поведение ссылок предсказуемым:

1. обычные URL в тексте должны становиться полноценными ссылками и попадать в существующий механизм отслеживания переходов;
2. выбор цвета должен быть ограничен небольшим набором стандартных цветов;
3. добавление и редактирование ссылки должно соответствовать привычному сценарию почтовых редакторов;
4. пользователь должен иметь простой способ очистить лишнее форматирование вставленного текста.

## 3. Автоматическое распознавание URL

### 3.1. Требуемое поведение

Редактор или этап подготовки HTML должен распознавать самостоятельные адреса, начинающиеся с:

```text
http://
https://
```

и преобразовывать их в обычные HTML-ссылки.

Пример:

```html
<div>https://www.mgpu.ru/magistratura/</div>
```

должен стать эквивалентом:

```html
<div><a href="https://www.mgpu.ru/magistratura/">https://www.mgpu.ru/magistratura/</a></div>
```

После этого ссылка должна проходить через уже существующий механизм отслеживания переходов Письмолёта.

### 3.2. Ограничения безопасности

Автоматическое распознавание не должно:

- изменять уже существующие `<a>`-ссылки;
- повторно оборачивать ссылку в `<a>`;
- менять URL внутри HTML-атрибутов;
- обрабатывать адреса внутри служебного подвала письма;
- создавать ссылку из частей email-адреса;
- включать в ссылку завершающие знаки препинания, если они не являются частью URL;
- выполнять HTML или JavaScript из пользовательского ввода;
- разрешать опасные схемы, включая `javascript:`, `data:` и аналогичные.

Поддерживаемые схемы для автоматического преобразования на первом этапе:

```text
http
https
```

### 3.3. Согласованность режимов

Результат должен быть одинаковым для:

- предпросмотра;
- HTML-части фактически отправленного письма;
- генерации записей `tracked_links`;
- отображения ссылки после сохранения и повторного открытия редактора.

Текстовая часть письма должна сохранять читаемый исходный URL.

## 4. Упрощённый выбор цвета текста

### 4.1. Общий принцип

Убрать полную палитру и произвольный выбор цвета.

Вместо неё показывать компактный набор из 10 стандартных цветов. Пользователь выбирает цвет одним нажатием по образцу.

### 4.2. Набор цветов

Точный визуальный набор уточняется при реализации с учётом контрастности, но должен включать базовые варианты:

1. чёрный;
2. тёмно-серый;
3. серый;
4. красный;
5. оранжевый;
6. жёлтый или тёмно-жёлтый, читаемый на белом фоне;
7. зелёный;
8. синий;
9. фиолетовый;
10. фирменный или дополнительный акцентный цвет.

Требования:

- без градиентной палитры;
- без ввода HEX/RGB;
- без системного color picker;
- текущий выбранный цвет должен быть виден в панели;
- должен быть отдельный понятный способ вернуть цвет текста по умолчанию.

## 5. Стандартный сценарий добавления ссылки

### 5.1. Открытие

Кнопка со стандартной иконкой цепочки открывает компактное всплывающее окно рядом с панелью инструментов.

### 5.2. Создание ссылки

При выделенном тексте окно должно содержать:

- заголовок `Ссылка`;
- одно поле URL с placeholder `https://`;
- основную кнопку `Сохранить`;
- вторичную кнопку `Отмена`.

После сохранения выделенный текст становится ссылкой.

При отсутствии выделенного текста допустим один из двух сценариев, который нужно выбрать при реализации:

- вставить URL как текст ссылки;
- показать дополнительное поле `Текст ссылки`.

Для MVP предпочтителен первый вариант как более простой.

### 5.3. Редактирование существующей ссылки

При установке курсора внутрь ссылки кнопка должна открывать текущее значение URL.

Во всплывающем окне должны быть доступны:

- изменение URL;
- сохранение;
- отмена;
- удаление ссылки с сохранением видимого текста.

### 5.4. Валидация

Редактор должен:

- автоматически обрезать пробелы по краям;
- принимать `http://` и `https://`;
- при вводе домена без схемы либо явно добавлять `https://`, либо показывать понятную ошибку; поведение должно быть единым во всех местах;
- отклонять пустой URL;
- отклонять опасные схемы;
- сохранять введённое значение при ошибке.

## 6. Очистка форматирования

Добавить отдельную понятную команду `Очистить форматирование`.

Она должна удалять у выделенного текста лишние стили, принесённые из внешних редакторов и сайтов, в том числе:

- `font-family`;
- `font-size`;
- `white-space`;
- цвет фона;
- произвольные inline-стили, не поддерживаемые редактором.

При этом по возможности сохраняются:

- текст;
- абзацы и переносы строк;
- списки;
- ссылки;
- базовое жирное, курсивное и подчёркнутое начертание.

Нельзя повреждать служебный подвал письма.

## 7. Совместимость с текущим трекингом

Новая логика не должна менять существующую модель трекинга.

Требования:

- для каждой отслеживаемой ссылки и получателя создаётся запись текущего формата;
- переход идёт через существующий endpoint Письмолёта;
- после фиксации клика пользователь перенаправляется на исходный URL;
- существующие записи `tracked_links` и `click_events` остаются читаемыми;
- прямые служебные ссылки, включая ссылку отписки, не должны ошибочно попадать в пользовательскую статистику кликов;
- предпросмотр не должен создавать фиктивные клики;
- повторное сохранение письма не должно бесконечно повторно переписывать уже обработанный трекинговый URL.

## 8. Наблюдаемость и интерфейс

В редакторе желательно явно пояснить, что ссылки в отправленном письме могут использовать технический переход Письмолёта для учёта кликов.

Формулировка должна быть короткой и не перегружать основной сценарий.

Статистика кликов должна продолжать отображаться отдельно от данных Mail.ru Postmaster. Метрики PM-4 и внутренний click tracking не объединяются и не подменяют друг друга.

## 9. Тесты

### 9.1. Автоматическое распознавание URL

- [ ] Одиночный `https://` URL преобразуется в ссылку.
- [ ] Одиночный `http://` URL преобразуется в ссылку.
- [ ] Несколько URL преобразуются независимо.
- [ ] Уже существующий `<a>` не оборачивается повторно.
- [ ] URL внутри атрибута не изменяется.
- [ ] Завершающая точка или запятая не попадает в ссылку.
- [ ] Опасные схемы не становятся ссылками.
- [ ] Служебный подвал не обрабатывается как пользовательское содержимое.
- [ ] HTML-часть и предпросмотр совпадают.
- [ ] Текстовая часть сохраняет читаемый URL.
- [ ] Создаются ожидаемые записи `tracked_links`.
- [ ] Клик создаёт `click_events` и перенаправляет на исходный адрес.

### 9.2. Цвета

- [ ] В меню ровно 10 стандартных цветов.
- [ ] Полная палитра и произвольный ввод отсутствуют.
- [ ] Цвет применяется к выделенному тексту.
- [ ] Цвет по умолчанию восстанавливается.
- [ ] Цвет сохраняется после повторного открытия редактора.

### 9.3. Ссылки

- [ ] Кнопка открывает стандартное всплывающее окно.
- [ ] Выделенный текст превращается в ссылку.
- [ ] Существующая ссылка редактируется.
- [ ] Ссылку можно удалить без удаления текста.
- [ ] Пустой URL отклоняется.
- [ ] Опасная схема отклоняется.
- [ ] Ошибка не стирает введённое значение.
- [ ] Клавиатурная навигация и фокус работают предсказуемо.

### 9.4. Очистка форматирования

- [ ] Удаляются внешние `font-family`, `font-size` и `white-space`.
- [ ] Сохраняются текст, абзацы и ссылки.
- [ ] Базовое форматирование сохраняется по принятому правилу.
- [ ] Служебный подвал не изменяется.

## 10. Критерий готовности

Доработка считается завершённой, когда:

- обычный URL в пользовательском тексте становится полноценной и отслеживаемой ссылкой;
- существующие `<a>`-ссылки продолжают работать без двойной обработки;
- выбор цвета состоит из 10 стандартных вариантов;
- добавление, редактирование и удаление ссылки выполняются через привычное всплывающее окно;
- доступна очистка внешнего форматирования;
- предпросмотр соответствует фактическому письму;
- полный набор автоматических тестов зелёный;
- production smoke подтверждает доставку, корректный переход и фиксацию клика.

## 11. Связанные направления

Изменение относится к техническому направлению.

При добавлении пользовательского пояснения о click tracking может потребоваться синхронизация публичной справки и документов об обработке технических данных. До появления такой формулировки изменения в `docs/specification.md` и юридических документах не требуются.
