# Удаление legacy-интеграции Robokassa

Статус: код удалён, сборка и полный набор тестов зелёные; ожидаются очистка production-конфигурации, deploy и smoke-проверка  
Дата: 2026-07-10  
Ответственное направление: техническое

## Причина

Провайдер отказался работать с проектом. Рабочий платёжный сценарий уже реализован через Prodamus, поэтому параллельный Robokassa-контур удалён без изменения пользовательской модели оплаты.

## Выполнено

- [x] Удалены legacy-маршруты ResultURL, SuccessURL, FailURL и fake checkout Robokassa.
- [x] Удалён старый `PaymentEndpoints` и его подключение из `Program.cs`.
- [x] Prodamus оставлен единственным активным пользовательским платёжным endpoint-контуром.
- [x] Удалены `RobokassaPaymentOptions`, чтение `Robokassa:*` / `Robokassa__*` и их регистрация в DI.
- [x] Удалены `RobokassaPaymentModule` и `FakeRobokassaPaymentProvider`.
- [x] Удалена legacy-константа `RobokassaFakeProvider`.
- [x] Audit-события переименованы в нейтральные `payment_succeeded` и `provider_payment_confirmed`.
- [x] Тесты оплаты и административных уведомлений переведены на актуальный Prodamus-контур.
- [x] Сборка подтверждена зелёной.
- [x] Полный набор автоматических тестов подтверждён зелёным.
- [ ] Удалить Robokassa-переменные из `/etc/pismolet/pismolet.env` без вывода значений секретов.
- [ ] Выполнить production-deploy.
- [ ] Проверить `pismolet.service`, `https://app.pismolet.ru/health` и основной платёжный экран.
- [ ] Повторно проверить отсутствие активных Robokassa-упоминаний в `src` и актуальной технической конфигурации.

## Важные ограничения

- Исторические документы из `docs/Obsolete` не изменяются.
- Исторические данные уже созданных платёжных попыток не мигрируются и не переписываются этой задачей.
- Удаление Robokassa не должно менять настройки, callback-маршруты и подпись Prodamus.

## Синхронизация с юридическим направлением

Требуется отдельная вычитка `docs/legal/app_ui_legal_texts.md`: в документе остались исторические ссылки на готовность сайта для Robokassa. Технический контур уже удалён, но юридические формулировки должны быть обновлены владельцем раздела C без механической замены текста из технического чата.
