# Удаление legacy-интеграции Robokassa

Статус: завершено и внедрено в production 2026-07-10  
Дата: 2026-07-10  
Ответственное направление: техническое

## Причина

Провайдер отказался работать с проектом. Рабочий платёжный сценарий уже реализован через Prodamus, поэтому параллельный Robokassa-контур удалён без изменения пользовательской модели оплаты.

## Выполнено

- [x] Удалены legacy-маршруты ResultURL, SuccessURL, FailURL и fake checkout Robokassa.
- [x] Удалён старый `PaymentEndpoints` и его подключение из `Program.cs`.
- [x] Prodamus оставлен единственным активным пользовательским платёжным endpoint-контуром.
- [x] Удалены `RobokassaPaymentOptions`, чтение `Robokassa:*` / `Robokassa__*` и их регистрация в DI.
- [x] Удалены `RobokassaPaymentModule` и `FakeRobokassaPaymentProvider`.
- [x] Удалена legacy-константа `RobokassaFakeProvider`.
- [x] Audit-события переименованы в нейтральные `payment_succeeded` и `provider_payment_confirmed`.
- [x] Тесты оплаты и административных уведомлений переведены на актуальный Prodamus-контур.
- [x] Удалены последние брендовые отрицательные проверки из активных UI-тестов.
- [x] Сборка подтверждена зелёной.
- [x] Полный набор автоматических тестов подтверждён зелёным.
- [x] Пять переменных `Robokassa__*` удалены из `/etc/pismolet/pismolet.env` без вывода значений секретов.
- [x] Production-deploy выполнен штатным `deploy-pismolet` без прежнего `env -u Robokassa__...` workaround.
- [x] `https://app.pismolet.ru/health` вернул `{"status":"ok"}`.
- [x] Legacy URL Robokassa проверены как недоступные.
- [x] За последние 10 минут после deploy в `journalctl -u pismolet.service -p warning` нет записей.
- [x] Основной Prodamus-сценарий подтверждён зелёными endpoint/UI-тестами до deploy.
- [x] В активных `src` и `tests` репозитория больше нет упоминаний Robokassa.

## Production-результат

Production успешно работает на кодовой базе без runtime-зависимости от Robokassa. Проверенный deploy был выполнен после fast-forward до `b3ebbfdbfdbaa98aca413272b43895a04265fe6c`; последующий commit `208e147b4df62dba43a23c19257794dcfcb47ced` удаляет только устаревшие отрицательные проверки из тестового файла и не меняет production runtime.

Первый повторный запуск deploy был безопасно остановлен preflight-проверкой из-за локальных каталогов `bin/` и `obj/`. После их удаления рабочее дерево стало чистым, повторный deploy завершился успешно. Откат приложения из-за этой preflight-остановки не потребовался.

## Важные ограничения

- Исторические документы из `docs/Obsolete` не изменяются.
- Исторические данные уже созданных платёжных попыток не мигрируются и не переписываются этой задачей.
- Удаление Robokassa не меняет настройки, callback-маршруты и подпись Prodamus.
- Упоминания Robokassa в историческом описании выполненной задачи допустимы; они не означают наличие активной интеграции.

## Синхронизация с юридическим направлением

Требуется отдельная вычитка `docs/legal/app_ui_legal_texts.md`: в документе остались исторические ссылки на готовность сайта для Robokassa. Технический контур уже удалён, но юридические формулировки должны быть обновлены владельцем раздела C без механической замены текста из технического чата.
