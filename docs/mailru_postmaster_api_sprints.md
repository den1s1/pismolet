## 1. Назначение

Документ переводит интеграцию Mail.ru Postmaster и связанные меры повышения качества доставки в самостоятельно выкатываемые production-спринты и является единым трекером их статуса.

Каждый спринт должен:

- давать законченный технический результат;
- быть совместимым с работающим production-контуром;
- иметь автоматические тесты и production smoke-проверку;
- допускать отключение или откат без остановки отправки писем;
- не делать Mail.ru Postmaster критической зависимостью пользовательского сценария.

## 2. Система статусов

| Статус | Значение |
|---|---|
| `не начат` | Работы не начинались |
| `подготовка` | Уточняются детали, зависимости, доступы или схема |
| `в работе` | Идёт реализация |
| `на проверке` | Код готов, выполняются тесты, review или smoke-проверка |
| `готов к выкладке` | Все проверки пройдены, ожидается production-деплой |
| `внедрён` | Развёрнут в production и подтверждён smoke-проверкой |
| `наблюдение` | Развёрнут, идёт период накопления данных и оценки поведения |
| `заблокирован` | Есть внешняя или внутренняя блокирующая зависимость |
| `отложен` | Решение сознательно перенесено |
| `отменён` | Решено не реализовывать |

Правила:

- при смене статуса обновлять сводку и карточку спринта;
- после начала разработки указывать commit SHA;
- завершённые задачи отмечать `[x]`, незавершённые — `[ ]`;
- после production-внедрения указывать дату выкладки и результат smoke-проверки;
- каждую смену статуса добавлять в журнал.

### Решение по OpenDKIM

Не требуется добиваться появления `Precedence`, `List-Unsubscribe-Post` или `X-Postmaster-Msgtype` в `DKIM-Signature h=` любой ценой. Production-эксперимент с добавлением этих имён в `OversignHeaders` привёл к `dkim=fail reason=signature_incorrect` и был немедленно откачен. Рабочая конфигурация остаётся:

```text
OversignHeaders         From
```

Подробности зафиксированы в `docs/mailru_postmaster_api_operations.md`.
