# Спринты внедрения Mail.ru Postmaster API

Статус документа: активный трекер реализации  
Дата создания: 2026-07-09  
Контур: production  
Связанный план: `docs/mailru_postmaster_api_integration_plan.md`  
Ответственное направление: техническое

## 1. Назначение

Этот документ переводит план интеграции Mail.ru Postmaster API в набор самостоятельно выкатываемых production-спринтов и служит единым местом для фиксации их статуса.

Каждый спринт должен:

- давать законченный технический результат;
- быть совместимым с работающим production-контуром;
- иметь тесты и production smoke-проверку;
- допускать отключение или откат без остановки отправки писем;
- не делать Mail.ru Postmaster критической зависимостью пользовательского сценария.

## 2. Система статусов

Допустимые статусы:

| Статус | Значение |
|---|---|
| `не начат` | Работы не начинались |
| `подготовка` | Уточняются детали, зависимости, доступы или схема |
| `в работе` | Идёт реализация |
| `на проверке` | Код готов, выполняются тесты, review или smoke-проверка |
| `готов к выкладке` | Все проверки пройдены, ожидается production-деплой |
| `внедрён` | Развёрнут в production и подтверждён smoke-проверкой |
| `наблюдение` | Развёрнут, идёт период накопления данных и оценки поведения |
| `заблокирован` | Есть внешняя или внутренняя блокирующая зависимость |
| `отложен` | Решение сознательно перенесено |
| `отменён` | Решено не реализовывать |

Правило обновления:

- при смене статуса обновлять таблицу сводки;
- в карточке спринта указывать дату обновления;
- после начала разработки указывать ветку или набор commit SHA;
- после production-внедрения указывать дату выкладки и результат smoke-проверки;
- незакрытые задачи оставлять без отметки `[ ]`, завершённые отмечать `[x]`.

## 13. Порядок обновления трекера

При начале работ:

1. В сводке сменить статус на `в работе`.
2. В карточке спринта обновить статус и дату.
3. Добавить запись в журнал.

После завершения кода:

1. Отметить выполненные задачи.
2. Указать commits.
3. Перевести статус в `на проверке`.

После зелёных тестов:

1. Перевести статус в `готов к выкладке`.
2. Зафиксировать результат проверок.

После production-деплоя:

1. Указать дату выкладки.
2. Записать результат smoke-проверки.
3. Перевести статус в `внедрён` или `наблюдение`.
4. Обновить общую сводку.
5. Добавить запись в журнал статусов.
