## 1. Результат инкремента

В production развёрнут локальный read-only контур статистики конкретной рассылки Mail.ru Postmaster и отдельный блок в административной карточке рассылки.

Реальная синхронизация PM-4 контролируемо включена:

```text
MailruPostmaster__MailingMetricsEnabled=true
MailruPostmaster__MailingMetricsBatchSize=1
```

Первый production smoke выполнен по одной реальной завершённой рассылке и каноническому `msgtype`. Mail.ru API успешно вернул `200`, но данных по рассылке пока нет. Это состояние обработано без создания искусственных нулевых метрик.

PM-4 остаётся некритичным контуром наблюдаемости: инкремент не меняет правила SMTP-отправки, модерации или допуска рассылок и не делает Mail.ru Postmaster критической зависимостью приложения.

## 6. Текущее состояние и ограничения

- PM-4 включён в production с временным ограничением `MailingMetricsBatchSize=1`.
- Первый реальный API-запрос успешен, но Mail.ru пока не вернул метрики выбранной рассылки.
- В БД есть одна запись состояния синхронизации и нет строк ежедневных метрик.
- Состояние «Данных пока нет» является ожидаемым и не считается ошибкой.
- До накопления реальных данных PM-4 остаётся в статусе `наблюдение`, а не `внедрён`.
- Автоматическое влияние показателей Postmaster на отправку, модерацию или допуск рассылок не вводится без отдельного решения PM-6.

4. После появления и проверки фактических показателей перевести PM-4 из `наблюдение` в `внедрён`.
5. Не менять правила SMTP-отправки на основании Postmaster до отдельного решения PM-6 и накопления достаточной истории.
